# WADE analytics reference batch
Tracks WADE-02, WADE-04, WADE-05 and groundwork for WADE-08. Run `sh tools/wade/test-analytics.sh` on JDK 17+; it includes the original kernel suite. No external dependencies or runtime registration.

## Implemented semantics
- Temporal correlation: 2–16 unique named stages, distinct source evidence, ordered (strict increasing event time) or unordered, inclusive timespan within half-open evaluation window, deduplication and deterministic witness, explicit UNKNOWN for incomplete data, scope conflict or work limit. At most 10k inputs / 250k search steps. This deliberately conservative reference contract is not a claim of Sigma conformance. Native tie handling, same-event membership, repeated stages, cross-window overlap, all-match enumeration and rule translation remain to be designed against pinned upstream.
- Entity risk: versioned policy, independent evidence-group maximum across families, family caps, bounded 0–100 score, half-life decay, confidence and criticality multipliers, deterministic projection and contribution explanations. This is a score, not compromise probability. Scope and evidence groups must be derived from trusted canonical IDs. Threshold state, persistent ledger, evidence-group resolution, policy calibration, authorization and native bypass are not implemented. Empty input returns zero for an explicitly supplied ledger, not proof of telemetry completeness. Extreme timestamp ranges require adapter validation.
- Behavioural baseline: median/MAD and configurable scale floor, prior-only samples, explicit approved training membership, minimum sample size, duplicate/conflicting history handling, UNKNOWN for incomplete coverage. Not a learning pipeline; upstream must establish sample observation/availability timestamps, training approval provenance, scope, seasonality, profile retention, feature versions and drift checks. This scalar baseline is not yet full UEBA.

## Qualification boundaries
Standalone Java checks use synthetic data, not real detection performance. No live Wazuh APIs, indexes, roles, schedules or incident code modified. No production claim. Before integration, require native artifact compatibility and WCS source contract, authoritative scope, bounded fetch, persistent state, error/unknown propagation, replay and adversarial workload tests, plus full-stack AGY qualification.
