# Cross-entity intelligence and durable local history

This isolated reference batch adds:

- A bounded ordered multi-entity witness search over 2–8 stages, canonical tenant/type/namespace identities, distinct evidence groups, event time and knowledge time. Adjacent stages must refer to the same entity or a supplied direct relation valid at both event times. Relations are treated as undirected adjacency for this prototype; relation-specific direction and endpoint type constraints remain outstanding. No transitive or IP-only identity joins. Evidence and relation receipts are returned. A matching receipt describes a witness, not a complete input snapshot. Completeness and receipt authenticity are caller assertions. Work exhaustion or invalid scope yields UNKNOWN; a NO_MATCH is meaningful only with externally verified complete inputs.
- Categorical novelty/rarity over approved, equal-duration, non-overlapping feature windows with approval cutoff at current window start. No automatic learning, peer groups, seasonal calibration or statistical significance claim. Intended for one categorical observation per window; not a general frequency distribution over all events.
- A local SQLite immutable-record ledger for feature, risk signal, alias and relationship records, with tenant/scope/version partitions, idempotent append, conflict rejection, availability-cutoff snapshots, checksum verification and explicit bounded snapshot withholding. Payloads are generic caller-supplied JSON, not authenticated typed feature records. Checksums are integrity checks, not signatures. The local query does not prove upstream coverage or enforce access control on a shared database file. No production persistence, retention, migration, encryption or live Indexer writes. Not connected to the Java risk/UEBA dispatch. Use private local lab storage only.

No real Indexer or Wazuh installation contacted. No runtime registration, live finding publication, production graph integration, or validated detection coverage.
