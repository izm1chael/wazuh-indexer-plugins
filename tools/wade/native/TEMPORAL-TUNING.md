# WADE temporal and tuning integration batch

Run: python3 -m unittest discover -s tools/wade/native -v (JDK 17+). 38 tests passed on the local fixture suite, including 30 existing tests and eight new tests; no live cluster contacted.

RegisteredTemporalEvaluator validates the immutable rule and selector digest, accepts a restricted agent-scoped WCS stage selector and invokes the existing Java TemporalCorrelation engine. Ordered and unordered modes, 2–16 distinct stages, witness source references, explicit missing-field and duplicate rejection, deterministic receipt, fixed closed windows and bounded work are tested. The simulated native runner stages and delivers actual temporal findings. Rule registration now allows both temporal mode names and rejects noninteger count limits. No native Sigma compatibility claim. Fixed windows can miss cross-boundary sequences; lookback, late reconciliation, all-match enumeration, verified stage content and real source identity remain open. The process bridge remains a qualification mechanism only.

tuning.py evaluates supplied paired champion/challenger labelled outcomes. It refuses review candidates when the cohort is too small, labelled decisions are unknown, previously detected malicious cases regress, protected attack cases fail or false positives do not decrease. Unlabelled outcomes are not treated as benign. It issues a deterministic review receipt and always requires human approval. It never modifies rules. Actual disposition ingestion, provenance of paired replay and protected labels, representative sample qualification, statistically supported improvement, proposal creation and persistent approvals remain unimplemented. The minimum sample defaults are illustrative policy values, not evidence of significance.

No existing Wazuh source/build/role/scheduler code touched. No production activation. Risk and behavioural feature histories, their dispatch, graph fusion and native plugin qualification remain open.
