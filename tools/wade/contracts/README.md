# Candidate native storage contracts (not installed)

The three composable index template bodies in this directory are proposals for an isolated WADE namespace; no bootstrap, automatic installation, writes, policies or roles are included. Exact names cannot match the existing wazuh-events-v5* or wazuh-findings-v5* templates. Static checks: python3 tools/wade/contracts/test_contracts.py. Acceptance by the actual pinned Indexer, index creation, write/read round trips and permissions are not tested.

- rule-revisions: immutable create-only version documents; future lifecycle registry/active pointer is separate. Canonical selector bytes and digest verification required at adapter boundary.
- job-state: lease, revision, fence, checkpoint and pending output in one document. Production compare-and-set must use OpenSearch seq_no and primary_term plus semantic fence checks. Acknowledge only after durable idempotent consumer delivery; failure/timeout requires re-read. Null owner/expiry for inactive leases, not Instant.MIN. Do not use bulk indexing as a multi-document transaction.
- finding-revisions: immutable finding revisions; deterministic IDs, nested (index name, UUID, document ID) source references, explicit revision/status for future reconciliation. Require a verified index UUID before publication. Current local kernel does not yet carry UUIDs. Latest-view pointer, delivery ledger, replay/audit retention, schema migrations and late correction/retraction are separate work.
- All documents have a tenant field, but this is not access control. Derive authorization scope from authenticated context, verify source document permissions, restrict writes to the trusted service, test DLS/FLS and role isolation, and never grant wildcard Wazuh index access. Base64/binary is not encryption. Bound payloads/strings/nested objects before indexing; strict mapping does not enforce required fields. date_nanos range and supported formats must be validated in adapter and cluster. Separate retention policies and shard sizing require local qualification; do not adopt the native findings policy blindly.

## WCS source admission audit (RC2 e2871f7d)

wcs/stateless/events/main/fields/subset.yml and plugins/setup/src/main/resources/templates/streams/events.json declare @timestamp, event.created, event.ingested, event.id and event.sequence. The event template also exposes wazuh.space.name. These are candidate fields, not guarantees of provenance, authorization or population. tests/content-manager/lib/payloads.py wcs_event creates @timestamp and event.action/kind but no event.ingested. Do not substitute event time or created time for trusted knowledge availability. Qualify event.ingested population, origin, clock skew, overwrite policy and missing-data behaviour on each source class; missing trusted availability => UNKNOWN for causal evaluation. The native finding schema lists event.doc_id and event.index but not event.ingested in its event subset; preserve the original event reference and verified availability rather than assuming finding time is source time.

Native search must enforce exact authorized streams/partitions, bounded query/time/page limits, stable PIT/search_after sorting with qualified unique tie-breaker, explicit timeout/shard/truncation failures, complete scope inventory and source watermark. Never use document-provided wazuh.space.name alone as an authorization boundary. Native event replay must demonstrate no cross-scope access or future availability leakage. No source adapter is implemented by these mapping fixtures.
