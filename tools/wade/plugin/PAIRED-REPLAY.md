# Paired temporal replay

PairedTemporalReplay runs two immutable revisions of the same tenant/rule on a single captured source cohort for each labelled case. It reads the wider lookback once, retains the same raw rows for both rule evaluations, checks availability cutoffs, executes the actual TemporalAdmission and CrossWindowCorrelation engines and exports the existing advisory Dashboard cohort schema. Each report retains per-case and aggregate digests binding rule definitions, case identity, label provenance reference, scope, time, source capture and evaluation results. The exported cohort JSON is intentionally advisory and omits raw source identity and receipt; it cannot authorize promotion. A trusted ReplayAuthority must verify labels, both definitions and source scope. Stable cross-partition snapshots and honest inventory/availability depend on the native reader/authority; they are not guaranteed by these interfaces. Limits: 1000 cases, 512 partition reads, 100000 returned rows across the report, per-policy input limits; reader errors propagate or incomplete outcomes withhold. No publication, rule edits or activation. Actual native source integration, durable receipt store, authenticated API and approval enforcement remain outstanding.

Local: six Java suites run together, 110 assertions (12 new). JDK 21, release 17, lint all and warnings as errors. Native plugin not compiled. Source and test blobs verified.
