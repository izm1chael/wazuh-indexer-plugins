## Completion-window correlation
CrossWindowCorrelation is a Java engine independent of OpenSearch. Supply a pre-matched, authorized, complete lookback [completion start - span, completion end), event availability and a verified watermark. Ordered or unordered witnesses must finish inside the current half-open completion window; earlier complete matches cannot hide a new completion. The rule version field must be a globally qualified immutable revision identity, not merely a shared version number. The scope must include canonical tenant/entity identity, and source keys must include concrete index UUID and document identity. Caller authority is not implemented. The algorithm returns one deterministic witness per policy/scope/window with a stable logical finding ID and receipt binding admitted inputs; it is not all-match enumeration. Future-available evidence is excluded, and unknown coverage, input or work exhaustion withholds decisions. Later evaluation of the same completion window can keep the logical ID; persistent revision/retraction, late scheduling and output reconciliation are still required. This engine is not yet connected to the existing Python runner or native scheduler, which still operate fixed windows. No native Sigma conformance claim.
