# Native window document adapter

IndexWindowStore implements the in-process WindowService Store and Sink interfaces. Its narrow Backend interface is intended for authenticated OpenSearch document operations: GET with verified not-found semantics, create-only, and conditional replace using the returned sequence number and primary term. It does not implement an actual OpenSearch client or expose a REST route. No cluster access was attempted.

Reconciliation state and pending publication are encoded together in one versioned bounded binary envelope with SHA-256 integrity verification and redundant indexed metadata. This keeps the accepted decision and its publication intent atomic at the document level. Writes require explicit enablement. Publication delivery is create-only; an existing document is accepted only when its full canonical contents match. A failed or ambiguous delivery leaves pending intent intact. The backend must distinguish verified conflict/not-found from authorization, transport and cluster failure, enforce tenant scope and durable acknowledgement, and never silently coerce source contents. The adapter's checksum detects accidental corruption, not hostile writes by an authorized attacker. It is not a security boundary. Backend credentials must not be supplied by untrusted users. Document state transitions assume callers use WindowService; the store is not an external API.

Candidate strict mappings: wade-v1-window-reconciliation and wade-v1-window-publications. Both are unregistered. Publication sources are bounded opaque reference strings, not independently verified structured source identities. A future native source adapter must resolve authorized immutable source references; case management must consume revisions by logical ID and action, never delete original evidence. Retention, durable consumer cursors, job leases, replay fairness, checkpoint advancement and revoked-rule outbox drainage need explicit policy. WindowService NO_CHANGE can mean either accepted evaluation with no publication or idempotent replay, so a scheduler must inspect durable accepted state and not infer advancement from return status alone.

The last suite exercises a simulated Backend with exact sequence/term CAS and actual WindowService. Two static mapping tests pass with python3 tools/wade/contracts/test_window_contracts.py. Earlier complete suites not rerun; required artifacts and full checkout unavailable. The independent Gradle project includes this class but is still unbuilt. Native backend, source and authority implementations, strict mapping roundtrip, two-node conflict and failover qualification, privileges, throughput, scheduler and dashboard are open. No installation, live writes or incident branch changes.
