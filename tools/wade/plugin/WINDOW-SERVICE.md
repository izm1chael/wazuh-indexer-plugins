# Native in-process execution service and scheduling plan

WindowService composes the real CrossWindowCorrelation and FindingReconciliation engines without subprocesses. It uses explicit ports for authenticated authority, immutable approved policy, complete pre-matched source snapshots, atomic state/outbox CAS, and immutable durable delivery. Request identity binds a typed namespace/tenant/entity and policy to the completion window. Authorization and rule admission precede source reads and state staging; publication permission is checked before staging and recovery. These are interface calls, not an implementation of OpenSearch Security. The principal and policy must come from trusted adapters, never arbitrary request input. Source scopes and coverage are not independently verified by this service.

A successful evaluation stages its publication and accepted state together. A pending publication takes priority over re-evaluation. The sink must create-only or verify an exact duplicate, and return only after durable delivery. Retry after an ambiguous failure is safe only with that sink contract. Acknowledgement uses a separate CAS token. Incomplete input cannot retract; unchanged evidence does not republish. Requests for disabled/retired rules currently cannot recover pending output; production needs an explicit authorized drain/quarantine policy. Authorization revocation races must be handled by the actual storage and source security boundary, not these callbacks. The service does not itself acquire leases, create a durable job checkpoint, enforce wall-clock query limits, or schedule work. CAS prevents stale state writes but is not a distributed scheduler.

WindowPlan returns bounded forward windows and recent completed windows eligible for reconsideration, with cadence, grace and late horizon. It does not advance any checkpoint or ensure fair selection of older late windows when the budget is exhausted. The caller must supply the persisted checkpoint, trusted clock, and enforce a durable fair scheduling policy. This is not a running job scheduler.
