# Temporal job execution and cursor persistence

TemporalJobRunner invokes the real in-process WindowService for one eligible forward or late window. It binds the job to scope, immutable rule policy, cadence, grace, late horizon and origin; acquires a CAS lease; handles pending publication before reevaluating; and advances the cursor only after reading an accepted evaluation at the tick cutoff with no pending publication. Incomplete decisions retain the cursor, ambiguous errors retain the lease for expiry/recovery, and expired owners cannot advance the job. Late sweeps move a separate cursor and wrap within the configured origin and horizon. A blocked late window can stall the sweep until recovery or horizon expiry. Runtime must schedule both forward and late quotas.

IndexTemporalJobs supplies concrete document encoding, scoped create-only provision and sequence/primary-term CAS. It uses a new unregistered strict mapping wade-v1-temporal-jobs; the native backend candidate must permit exactly that index for GET/create/CAS only. No automatic provisioning or runtime registration. No changes to native finding indices. This adapter assumes trusted service callers; it is not a public mutation API. Job-cursor fencing prevents stale checkpoint advancement but is not a cross-document atomic fence on WindowService state/publications: actual authorization/fence enforcement at the window write boundary and two-node tests remain required. Do not activate before that and the native registry/source identity/availability authority are implemented. Native OpenSearch adapter is uncompiled.

Eight local Java suites compiled with JDK 21, --release 17 -Xlint:all -Werror: 136 assertions total (12 paired replay, 15 job runner, 11 job document new in this pass). The new job tests use simulated cursor and document backends, not real Indexer. No live scheduler or cluster operations performed.
