# Late-evidence reconciliation contract

The Java completion-window matcher now returns separate logical window/finding identity, witness digest and full evaluation receipt. The witness digest binds selected events and their stage membership; the receipt binds the full admitted snapshot and evaluation cutoff. FindingReconciliation.evaluateCrossWindow performs the actual evaluation and constructs a decision internally, not from a caller-supplied arbitrary negative result.

The reference state machine supports monotonic accepted evaluation cutoffs, expected-revision checks, idempotent equal-cutoff replay, first finding creation, evidence amendment, retraction after a complete negative and restoration using the same logical identity. An unchanged witness advances the accepted cutoff without new publication. UNKNOWN and NOT_READY never retract or advance accepted state. Publication intent has a deterministic ID. The adapter must validate the authority of input scope, policy, source coverage and evidence; arbitrary direct Decision construction is not an authorization boundary.

Production needs a native CAS transaction of state and pending publication, immutable revision history, verified receipt, idempotent consumer and lease fencing. Never write over existing native findings or delete case evidence. Retractions are logical revisions, not incident closures. Incident consumers must display the historical evidence and current status. This reference does not schedule reevaluation, publish findings or persist state; the earlier fixed-window runner is unchanged. A complete negative from an unauthorized or partial source must never retract a production finding. No automatic suppressions.
