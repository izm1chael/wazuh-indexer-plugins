# Authenticated detection releases and post-release review

Development candidate for WADE-06 and WADE-11; builds on the existing native rule replay and campaign pack. No production or upstream activation. This replaces the previous reusable digest-only path **when native production freeze is enabled**. Default compatibility remains unchanged when freeze is false; do not claim all production paths protected until integrated configuration/RBAC is qualified.

## Enablement and role boundary

Provision the new fixed strict hidden index .wazuh-detection-releases-v1 through setup:

```yaml
plugins.setup.detection.releases.enabled: true
plugins.content_manager.promotion.production_frozen: true
plugins.content_manager.promotion.approved_plan_sha256: ""
plugins.content_manager.promotion.approved_plan_expires: ""
```

Node settings, all nodes consistent; index provisioning before enabling production approval. No migration of old release data. Ledger gate default false; existing native freeze default false. New exact setup action grants cluster:admin/wazuh/detection/release_submit, release_read, release_day, release_review, no underlying index permissions in fixtures. Native promotion grants remain independently required for deployment. Use three distinct authenticated usernames (submitter, independent reviewer, deployer); assign reader access to both humans as needed. The dashboard uses asCurrentUser, never an admin transport. Review route requires read plus review. Native gate uses the fixed ledger internally under stashed context, then restores the original authenticated caller for native resource actions. No raw content or external AI call. Shared metadata is visible to authorized readers regardless of source DLS/FLS. Hidden index is not itself an ACL: deny direct access, wildcard write, delete, rollover/restore, and config changes to nonoperators. Existing operator and cluster-admin trust remains. Protect evidence and backups.

## Durable lifecycle

Submit eligible campaign pack in dashboard /incidents/detection-releases. Server parses the existing full local pack, checks blockers, computes SHA256 of **the exact UTF-8 text submitted** (not reserialized JSON; whitespace/newline changes change digest), and sends a compact evidence summary to the indexer. Direct API POST /_plugins/_setup/detection-releases/submit accepts exact {id,evidence}, id = native captured plan SHA256, evidence exact hashes of pack/Test/Custom/preview/labels, integration, cluster, space, dataset, changed_rules, historical_events, prospective_events, prospective_seconds, and per-rule historical_metrics and prospective_metrics. Request maximum 16 KiB; large packs are reduced to summary; over-budget summary rejected. Setup independently validates all rule metrics, population conservation and initial qualification thresholds: at least 24h prospective, ten positives and ten negatives per changed rule per partition, zero unknown/lost positives/new false positives, historical improvement. Summary is an assertion derived from imported evidence, not server-attested replay or truth. No raw events, labels, complete pack, or source references in shared ledger; retain original exact pack and supporting receipts privately.

Create-only plan SHA256 document ID; no reset, delete, resubmission or automatic replacement for same digest. State/revision:
- submitted/1: authenticated author and UTC server time.
- approved/2 or rejected/2: one independent authenticated reviewer, immutable reason, exact pack digest; approval specifies a third distinct deployer and canonical UTC expiry strictly after review, at most 3600 seconds after review. Reject has null deployer/expiry; terminal.
- reserved/3: irreversible native CAS before engine/consolidation. No retry if result lost.
- native_reported/4: native HTTP-style status/time persisted with CAS. Native success or acceptance does not verify deployed rule matching, detector sync or engine state.

Read POST /read exact {id}; daily queue POST /day exact {day} (UTC midnight, <=50 exact records, no partial/truncation, current day allowed). Review POST /review exact {id,expected_revision:1,pack_sha256,decision,reason,deployer,expires}; actor derived from authenticated context, CAS stale state rejects. Dashboard requires reviewer to re-import the identical original pack text; hashes and summary must match stored record before review. A direct authorized reviewer attests original evidence independently; no cryptographic signature or authenticated label provenance. Reviewer must reconcile all changed rule content and complete preview against native plan. No revocation or renewed approval for same plan in this iteration: expiry or operator clears pin; avoid accidental old-config reuse. No automatically renewable lock. Use a new independently reviewed changed plan after expiry or rejection; if same plan must be recovered, explicit operator incident/change-control investigation required rather than deleting ledger.

## Native promotion boundary

Use native read-only review_plan_only request to obtain exact gathered plan hash. Existing config hash and expiry remain required, now additionally require central approved record matching exact plan, preview SHA256, rule UUID set, intended deployer and expiry. For frozen Test -> Custom, restrict to existing distinct 1..20 rule UPDATEs, all other resource lists empty. Gathered rule apply keys and old snapshots must equal reviewed set; old target documents must exist. Compare SHA256 of native changes object to the Python preview digest (sorted JSON object keys, ASCII UUID and operation values; order of arrays preserved); any ordering/representation drift blocks. No decoder/integration/normalization/add/remove release in this initial gate. Native Draft -> Test and read-only plan gathering unaffected. Review-only does not reserve. If freeze disabled native legacy behavior remains.

On matching plan, CAS exact ledger row approved -> reserved before applying native plan. Two nodes racing the same record can only commit one reservation under normal OpenSearch CAS semantics. Only the original authenticated deployer can reserve. Recheck expiry after reservation; if expired, leave consumed and block. Preserve original caller context through the internal ledger operations. If native normal response arrives, store status and timestamp with CAS; if callback/write fails or process crashes, leave reserved, no automatic repeat. No cross-plan global lock, no post-gather resource CAS, no guarantee about other CTI sync or direct content changes. Require coordinated change freeze and all-node consistent configuration. Plan hash binds captured plan, not entire compiled mapping or all cluster state; preview hash binds request diff, not proof imported replay content corresponds to captured plan. Human must verify raw evidence and actual plan. This is single-use **per stored plan ID**, not atomic deployment or cryptographically signed evidence. Do not delete or restore ledger behind active approvals. Clear hash and expiry after controlled attempt. Independently inspect actual native Custom state, detector synchronization and rollback; unresolved reservation needs manual incident recovery. No automatic rollback or native promotion proxy.

## Post-release verifier

tools/native_release_monitor.py --config <reviewed JSON> --output <new report.json>. Read-only account with release_read and native content/event/finding read grants, no submit/review/promote or writes. TLS fixed origin explicit CA no proxy/redirect, WAZUH_RELEASE_MONITOR_PASSWORD environment. Config contains exact endpoint, username, ca_file, plan_sha256 and four canonical UTC second boundaries baseline_from/baseline_until/post_from/post_until. Requires native_reported revision4 status 200/202, validates record identity/chronology. Exact equal nonoverlapping intervals up to 24h each, baseline ends before or at reservation, post begins at or after native report, end >=120s ago, baseline no older than 30d. Scope/rules from stored evidence only. Reads native integration and all associated rule documents from Test and Custom. Test full snapshot hash must still match reviewed Test fingerprint; no inference if changed. Compare exact document body SHA256, excluding index/seq_no/space wrapper; any representation drift shows mismatch. Compare all integration rule document map digests, and integration document digest; no compiled query or SAP parity claim. Recheck release and content at end; no transactional snapshot.

Search normalized event and findings streams independently by exact cluster/space/dataset/time and reviewed rule UUID aliases for findings; source projection only scope/time/rule fields, cap 2,000 events and 2,000 findings per window, exact totals/no partials, concrete identity and scope/half-open time validation, conflicting aliases fail. Retain aggregate counts and population-reference/version digests only, no raw source or refs. Report volume deltas not accuracy, no event-to-finding join, no causal attribution. Missing fields or unavailable sources block or appear absent depending on exact native term selection; zero does not prove absence/completeness. No automatic rollback or deployment verification. Dashboard imports local report and binds exact release/pack/scope/chronology/content digests and counts, explicitly marks mismatch and limitations. No scheduled monitor loop yet; explicit one-shot, examples/native-release-monitor.example.json. Source and content permissions require live qualification.
