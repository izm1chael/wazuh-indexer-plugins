# Analyst feedback on AI assessments

A distinct ai_feedback grant allows the current incident owner to submit feedback on an assessment at the exact current incident revision. The input contains only assessment UUID, digest hash, revision, mode, usefulness rating and hypothesis agreement/disagreement/not reviewed. It is an analyst attestation, not verified model provenance; a direct authorized caller can submit its own IDs and hashes. No raw digest, provider content, rule or finding IDs, or free-text feedback is accepted. The server derives actor/time, atomically records one feedback per assessment UUID per incident (100 lifetime cap), and records the scalar fields in delivered audit history. No automatic learning, classification change, closure, or rule tuning. Feedback is permitted on closed incidents without changing closure or resolution timestamps; current closed classification is separately recorded as a snapshot, not a finding-level label. Revision changes require a fresh assessment. This changes updated_at/revision, including closed incidents, as an audited mutation. Actual authorization, mapping upgrades, CAS replay, direct caller misuse and delivery recovery must be locally qualified. Do not use attested usefulness or agreement as ground truth or an automatic training signal.
