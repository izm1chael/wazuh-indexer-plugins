# Advanced entity investigation and case hunt bookmarks

Development candidate, not production qualified. Uses existing native findings, shared incident links and incident CAS/outbox. No TIP expansion, raw event analytics, inferred identity or additional endpoint action.

## Entity investigation

POST /_plugins/_setup/incident-entity/investigate requires the distinct cluster:admin/wazuh/incident/entity_investigate permission and incidents enabled, exact authenticated principal. This is a combined permission to execute the existing bounded hunt and read minimal shared-SOC case associations; it is intentionally separate from hunt_read and ordinary incident_read. The request uses the existing strict 16 KiB four-field hunt parser (field, values, from, until), allowlisted 15 fields, up to 20 exact values, max seven days and 100 findings. No arbitrary references, indices, DSL or case IDs are supplied by caller. Search findings under original caller context, confirm exact matches in source, reject partial or excessive hits. Restore caller context and verify principal before searching fixed hidden incident index. Shared hunt service permits are reused; one entity investigation per service instance and one dashboard hunt/investigation per process.

The second search joins the validated visible findings to nested findings references in .wazuh-cases-v1. Group by concrete index with terms on document IDs in that same nested row; never independently OR index and document IDs. Validate exact pairs again against source and finding-count consistency. Maximum 50 cases, exact total required; timeout, partial shards, duplicate/malformed hits and excess count fail the whole investigation. Empty findings return empty cases without case lookup. Only case UUID, revision, status, severity and matching visible reference pairs returned, no title, notes, owner, unrelated refs or count of unrelated refs. Cases sorted by matched distinct finding count then UUID. Scope caller_visible_hunt_shared_case_links. Does not enforce per-case ACL (single-SOC shared case model). Reading a full case requires ordinary incident_read. Source search and case search are separate non-atomic observations; source visibility can change after search, and case links can change or lag index refresh. No guarantee of absence, causality, duplicate incidents, shared actor identity, current permission at display time or completeness beyond the exact retained search. Generic error/timing can reveal bounded failure conditions. Validate actual OpenSearch DLS/FLS and mappings, no elevated findings search.

Dashboard extends existing hunt with a separate Investigate entity and related cases action. Entity activity timeline uses up to 24 contiguous half-open UTC buckets, counts distinct findings, exact-value filter, exact related-case candidates and navigable case IDs. Evidence relationship explorer shows observed value -> concrete finding -> current linked case edges for selected finding, no inferred edges. Graph is an interactive adjacency explorer, not a full arbitrary graph database or cross-field entity resolver. Existing attach finding action still independently checks current source visibility, revision and ownership. Existing manual relationship assertions remain distinct.

Portable definitions are explicit copy/paste JSON with version format wazuh-exact-hunt-v1, only normalized query fields, no results or credentials, no localStorage or automatic execution. Loading validates allowlist, literal values and dates, then populates form for review; JSON.parse uses ordinary last-key-wins semantics for duplicate keys in this local import, not an execution or approval mechanism. Do not store sensitive queries in unapproved locations.

## Case-bound hunt bookmarks

New save-hunt-bookmark and withdraw-hunt-bookmark incident commands map to existing collaborate permission and current owner, open incident, revision and outbox checks. Save exact label and validated query; no search is performed and no result or evidence claims made. Canonical query uses sorted distinct literal values and normalized UTC millisecond-compatible bounds. At most twenty lifetime rows; duplicate currently saved canonical query conflicts, can save again after explicit withdrawal. Server-derived ID incident UUID:new revision, actor and timestamp. Withdraw records actor, timestamp, reason and revision, retains original definition and audit. Old records missing hunt_bookmarks are empty. No query is automatically replayed. Shared case readers see literal query values (including withdrawn definitions) in collaboration projection: analyst must explicitly confirm nonrestricted sharing, no per-case ACL or TLP enforcement. Do not save secrets or restricted finding values. UI confirmation is not an authorization mechanism or independent classification proof.

Additive unindexed hunt_bookmarks object to strict case mapping. Apply and verify before any upgraded incident writer starts, even with incidents disabled during migration; matched builds, backup and restore qualification. No additional hidden index. Full transition changes retained in internal activity, safe projection only bookmark ID. Dashboard case bookmark register supports prepare new query, save from incident entity pivot, explicit load and rerun, withdraw. Existing owner/CAS checks apply; stale views cannot mutate. Old collaboration response omission hides bookmark controls. Bookmark definition is not immutable finding evidence; use existing attach or evidence-register workflow for that.
