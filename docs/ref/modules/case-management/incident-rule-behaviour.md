# Advanced rule-specific behaviour analytics — rule_volume_v2

Development candidate, default off. This increment complements daily_volume_v1 with a longer, higher-cap exact-rule baseline and an opt-in daily observation ledger. It is still finding analytics, not a calibrated user/entity risk engine.

## Search and model

POST /_plugins/_setup/incident-behaviour/rule-assess requires cluster:admin/wazuh/incident/rule_behaviour_read and all three gates:

```yaml
plugins.setup.incidents.enabled: true
plugins.setup.incidents.behaviour.enabled: true
plugins.setup.incidents.behaviour.rule.enabled: true
```

All default off, matched node configuration required. Dedicated role fixture grants no private index rights; caller must also have appropriate native source permissions. Exact strict JSON fields: field, value, rule_uuid, day (canonical UTC midnight Z). One of the nine v1 entity fields, one exact literal, one canonical lower-case detection rule UUID, one completed comparison day. No wildcard, CIDR, arbitrary DSL, caller-selected index, external calls or raw-event search. IPv4 only. 28 preceding UTC days, comparison day [day, day+1d), 120-second grace (not a watermark).

One fixed native findings query over all 29 days with exact entity term and OR of wazuh.rule.uuid and rule.uuid. Request 2,001 hits, exact totals, no partial shards or early termination, 15-second search timeout, strict open indices. Reject >2,000 hits rather than sample counts. Revalidate every returned concrete reference, source rule identity using CorrelationPlanner.extract (conflicting rule aliases invalid), timestamp and exact caller-visible literal using IncidentHuntService.project. Reject duplicates and inconsistent data. No elevation or private case access. Per-instance semaphore 1 for expanded scans, separate from v1 hunt budget; dashboard shares hunt concurrency guard. Still a bounded source scan, not a high-volume aggregation or PIT-backed event engine; source field arrays and document sizes require real resource testing.

28 baseline daily counts, current count C, total S, active days A, same weekday maximum W (positions 0,7,14,21), median M and median absolute deviation D. Compute threshold T = max(5, W+3, ceil(2*S/28), ceil(M+3*D)). Integer representation: median_times_two = 2*M; mad_times_four = 4*D. Elevated rule volume requires >=7 active baseline days and C>=T. Other outcomes: no_observed_activity (S=C=0), newly_observed (S=0,C>0), sparse_baseline (S>0,A<7), within_volume_threshold (otherwise). These are descriptive heuristic classes, not benign/malicious labels, confidence estimates, or calibrated risk. Same weekday term is conservative, not full seasonality adjustment. Late arrivals, retention, rule changes, access changes and absent telemetry may change the result. Seven active days do not prove completeness. No claims of authentication success/failure or actual compromise based solely on rule UUID.

Response includes exact query, actor, observation time, total count, all 28 baseline daily counts, statistics/classification, and at most 20 earliest comparison finding references (timestamp/index/document ID). No raw source or full population export. Mark coverage search_complete_telemetry_unverified: exact search-result coverage is not ingestion/retention coverage. Dashboard independently recomputes statistics and verifies total/sample shape, not every source row (the complete population is not returned). Dashboard /incidents/rule-behaviour shows counts, threshold, median/MAD, daily chart, sample, and explicit broader entity hunt pivot for the comparison day (not rule-restricted). No automatic response, incident creation, AI prompt or scoring.

## Scheduled observation ledger

Opt-in tools/incident_rule_behaviour_runner.py, one approved policy per configuration/state file, one due day per invocation. Reuses analytics runner UTC/UUID/strict JSON/redirect helpers. Example JSON and systemd service/timer under examples/; not installed, enabled or run against live systems. HTTPS origin, explicit CA, no proxy or redirects, fixed POST route, environment WAZUH_BEHAVIOUR_PASSWORD, no credential in DB. Dedicated unprivileged source-read account and local system user; protect config, credentials, state directory and backups. State scope binds exact endpoint, username, CA path, deployment/policy IDs and version, field/value/rule and first day. Local deployment and policy identity are operator-defined, not remotely attested. Changing any configuration requires a new reviewed ledger; no silently reusing old state.

SQLite synchronous FULL; single-host flock; validate scope and contiguous day membership, no day before first day or skipped day, one immutable-by-runner INSERT per comparison day, transaction verifies next day under write lock. Failed request, validation, or insert retains cursor; retries only read-only search, never native action. Once committed no re-evaluation or overwrite by runner; late arrivals may make historical receipts stale. Backfill automatically limited to due day no older than seven days relative to now; older gap blocks and needs operator review. No arbitrary skip/rewind, no timer activation. Validate exact actor/query/window/model/scope, observed_at relative to end+grace and scheduler clock +/-300s, statistics recomputed, count conservation, sample exact reference/time bounds and uniqueness. Store counts, coverage, observed_at and SHA256 of canonical full report; no sampled document IDs, raw results or password. Scope includes sensitive entity literal and rule, so state is restricted data. Hash is local receipt digest, not signature or proof of unchanged source; original full report is not retained. SQLite ledger is append-only by runner, not tamper-resistant and not replicated or integrated into indexer incident storage. Local operator can inspect observations using SQLite, not a new dashboard history or incident API. No direct indexer writes, no automatic alert/incident or Agentic SOC integration. A dedicated source-read account can call other permitted source search actions; config pin restricts this runner, not the account globally.
